# Parcial1Datos
Pipeline de Datos: Extracción, Transformación, Calidad y AlmacenamientoEste repositorio contiene la implementación de un pipeline ETL (Extracción, Transformación y Carga) desarrollado en Python y ejecutado en Google Colab, diseñado para procesar un volumen masivo de datos respetando estrictos estándares de calidad y arquitectura.📋 1. Propósito del ProyectoAutomatizar el flujo de datos desde una fuente externa (API REST), aplicando procesos robustos de limpieza, normalización, validación de calidad y almacenamiento estructurado multiformato (CSV, Parquet y SQLite), minimizando la intervención manual y garantizando la reproducibilidad.🔌 2. Fuente de DatosNombre de la Fuente: Random User Generator APIEndpoint: https://randomuser.me/api/?results=500Formato de Origen: JSONVolumen: 500 registros dinámicos con atributos demográficos, geográficos y de contacto.🛠️ 3. Tecnologías UtilizadasPython 3.x: Lenguaje principal de programación.Google Colab: Entorno de ejecución en la nube.Pandas & NumPy: Manipulación, transformación y análisis tabular de datos.Requests: Consumo de solicitudes HTTP hacia la API REST.SQLite3: Almacenamiento relacional embebido.PyArrow: Generación de archivos optimizados en formato Parquet.🏗️ 4. Arquitectura del PipelineEl flujo de datos sigue una secuencia lineal estructurada para garantizar trazabilidad y control de calidad en cada etapa:[ Fuente API ] ➡️ [ Extracción HTTP ] ➡️ [ Datos Brutos (Raw DataFrame) ] 
                                                  │
[ Consumo / Análisis ] ⬅️ [ Almacenamiento (CSV, Parquet, SQLite) ] ⬅️ [ Validaciones de Calidad ] ⬅️ [ Transformaciones Significativas ]

Descripción del Pipeline y TransformacionesFases del Proceso:Extracción: Solicitud GET a la API para capturar un lote inicial de 500 registros crudos estructurados en formato JSON anidado.Exploración Inicial: Verificación de dimensiones, tipos de datos, conteo de nulos y revisión de estructura inicial.Transformaciones Significativas:Renombrado y Normalización de Columnas: Estandarización a nomenclatura snake_case (ej. user_id, full_name, country).Estandarización de Textos: Conversión de nombres completos a mayúsculas y correos electrónicos a minúsculas (str.upper() / str.lower()).Creación de Variables Derivadas: Creación de la columna categórica age_group mediante rangos etarios y extracción del dominio de correo (email_domain).Limpieza Estructural: Eliminación de campos redundantes y formateo de cadenas de texto especiales.Validaciones de Calidad de Datos:Verificación de volumen mínimo ($N \ge 500$).Control de unicidad sobre la llave primaria (user_id / UUID).Validación de formato mediante Expresiones Regulares (Regex) para correos electrónicos.Aserciones programáticas (assert) para impedir el paso de nulos en campos críticos.💾 6. Decisiones de AlmacenamientoSe optó por una estrategia de triple salida para cubrir diferentes necesidades de consumo:CSV: Garantiza portabilidad universal e interoperabilidad con herramientas ofimáticas o de visualización rápida.Parquet: Proporciona compresión columnar eficiente, ideal para entornos de Big Data y analítica avanzada.SQLite: Permite persistencia relacional local, facilitando la ejecución de consultas SQL complejas sobre los datos procesados.🚀 7.
